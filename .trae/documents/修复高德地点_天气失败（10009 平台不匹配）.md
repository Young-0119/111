## 失败诊断
- 日志显示 HTTP 200，但 body 为错误：`{"info":"USERKEY_PLAT_NOMATCH","infocode":"10009","status":"0"}`
- 结论：使用的 Key 与调用接口的平台不匹配（例如用 Android Key 访问 Web 服务 REST API）。需使用「Web服务」类型的 Key，或为当前 Key 配置正确的平台与安全设置。

## 修复方案
1. Key 规范与安全配置
- 将当前 Key 更新为「Web服务」类型（高德开放平台控制台申请），暂时关闭 IP 白名单或添加服务器出口 IP。
- 可选：开启数字签名校验（sig），我们在客户端支持签名计算（不暴露私钥），或推荐经后端代理完成签名。

2. 服务增强（代码改动）
- 在 `AmapService` 增加：
  - `setSecurityKey(secret: string)`（仅在本地调试时可用），根据高德签名规则计算 `sig` 参数并拼接 URL（参数排序 + secret 做 MD5）。
  - 错误体解析：当 `status!=1` 时记录 `info/infocode`，并返回“获取失败”。
- 保留现有调试日志：请求/响应码/正文摘要与解析结果，便于定位后续问题。

3. 使用指引
- 启动处在 `EntryAbility.onCreate`：
  - 优先使用新的 Web 服务 Key：`AmapService.setKey('<Web服务Key>')`
  - 如需本地签名调试：`AmapService.setSecurityKey('<密钥>')`

## 验收标准
- 使用正确的 Web 服务 Key 后，逆地理返回行政区字段，天气返回实时字段，UI 显示正常。
- 错误情况下输出详细 `infocode/info` 便于继续排查。
