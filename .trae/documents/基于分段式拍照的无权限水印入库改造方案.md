## 目标与范围
- 仅保留“水印照片”，原始照片不保留；拍后立即在系统相册可见。
- 用户只需一次点击快门，无额外弹窗/授权；不使用受限权限 `READ_IMAGEVIDEO`/`WRITE_IMAGEVIDEO`。
- 改造拍照主链路；视频与相册导入不在本次范围（保持现状）。

## 总体思路
- 启用 Camera Kit 分段式拍照：阶段一获取内存图片（PixelMap/Buffer），阶段二在应用侧完成水印合成后提交到图库。
- 移除“原片先入库 → 回调读取 → 再保存水印版”的旧路径，避免双份与权限依赖。
- 取消受限权限声明与请求；所有保存走分段式拍照的图库提交能力（官方合规路径）。

## 详细设计
### 一、分段式拍照接入
- 创建 PhotoOutput 时开启“分段式/内存回调”能力（参考官方指南）。
- 注册内存阶段回调（示例名：photoAvailable/内存图回调），回调参数提供原始帧的 `PixelMap/Buffer`。
- 在回调中：
  - 读取设备姿态与旋转（复用现有逻辑：`getPhotoDegree()`、`getPhotoRotation()`）。
  - 将原始帧转换为可编辑 `PixelMap`（若已是 `PixelMap`，直接进入处理）。
  - 调用水印合成链：`createWatermarkPixelMap()` → `compositeImagesCanvas()` 或像素复合作为降级。
  - 使用 `ImagePacker` 将结果编码为 JPEG（复用：`encodePixelMapToJpeg()`）。
  - 调用分段式拍照的图库提交接口完成入库（替代 `saveBufferToGallery()` 的 `applyChanges` 普通路径）。
  - 回调 UI 缩略图与 `uri`（复用：`setCallback(pixelMap, savedUri)`）。

### 二、水印合成策略
- 保持现有水印信息聚合：时间戳、地理信息、组织信息缓存与刷新（`getWatermarkInfo()` 链）。
- 合成顺序：
  - 首选 OffscreenCanvas 合成（`compositeImagesCanvas()`），失败回退像素合成（`compositeImages()`）。
  - 颜色空间保持 SRGB 或 DISPLAY_P3（HDR 时），与当前配置一致（`setColorSpaceBeforeCommitConfig()`）。
- 仅生成水印版；不再编码与保存原片（删除 `KEEP_BOTH/WM_ONLY` 中的原片保存分支：`camera/src/main/ets/cameramanagers/PhotoManager.ets:871-874, 890-892`）。

### 三、入库实现（分段式提交）
- 编码后获取 `ArrayBuffer`，调用分段式拍照的“提交到图库”接口：
  - 设置 `title`、扩展名 `jpg`、标记为相机照片（与现有 `saveCameraPhoto()` 意图一致）。
  - 返回 `file://media/...` 的最终 `uri`，作为缩略图跳转与查看依据。
- 严禁走普通 `photoAccessHelper.applyChanges()` 路径，避免权限依赖（删除或条件屏蔽）。

### 四、错误处理与兜底
- 回调处理内的守护：
  - 并发保护（已有 `isProcessingPhoto`）：忽略重入，避免多次提交。
  - 失败路径：
    - 合成失败：提示“拍摄失败，请重试”；不提交图库。
    - 编码失败：同上。
    - 提交失败：提示并保存在沙箱临时目录；提供“稍后导出”的入口（可在设置页开关）。
- UI 反馈：沿用闪屏与缩略图更新；失败时 toast。

### 五、兼容性与能力检测
- 启动时检测设备是否支持分段式拍照能力：
  - 若不支持，降级为 SaveButton 作为快门：
    - 用户仍一次点击；在控件回调中串行“拍内存→水印→以安全控件保存到图库”。
  - 降级时保留当前 `PhotoManager` 的水印链与编码链；替换提交接口为 SaveButton 的 `applyChanges` 上下文。

### 六、配置与安全
- 权限：保留 `CAMERA/MICROPHONE/MEDIA_LOCATION/LOCATION/APPROXIMATELY_LOCATION/INTERNET/ACCELEROMETER`；移除 `READ_IMAGEVIDEO/WRITE_IMAGEVIDEO`。
- 不记录或泄露 `uri` 与位置信息到日志（保留必要级别）。
- 资源释放：`PixelMap/ImageSource/PhotoAccessHelper` 按现有 finally 规范释放。

## 时序图（文字说明）
- UI 点击快门 → PhotoOutput 内存回调 → 生成水印 PixelMap → JPEG 编码 → 分段式提交到图库 → 返回 `uri` → 缩略图显示与可跳转系统相册。

## 验收标准
- 功能：每次拍摄仅生成水印版，系统相册可见；原片不出现。
- 交互：无额外弹窗；连拍不被打断；失败有提示且不生成半成品。
- 合规：移除受限权限，权限审核通过。
- 性能：单张水印合成+编码 ≤500ms，内存峰值控制在原图×2以内。

## 测试计划
- 单元：
  - 水印信息聚合正确性（组织/位置/时间）；像素合成结果尺寸与旋转正确。
  - 编码质量与 EXIF 元数据（旋转/方向）校验。
- 集成：
  - 分段式回调链路收敛；图库提交返回有效 `uri`。
  - 并发拍摄与重入保护（`isProcessingPhoto`）。
  - 失败兜底到沙箱与后续导出。
- 设备矩阵：前/后摄、HDR 开关、不同分辨率 Profile；不支持分段式设备的 SaveButton 降级路径。

## 开发步骤与里程碑
1) 清理权限声明与运行时请求（2处声明、2处请求）。
2) PhotoOutput 创建时启用分段式能力，注册内存阶段回调。
3) 将 `processSavedAssetWithWatermark(uri)` 改为 `processBufferWithWatermark(pixelMap)` 流程。
4) 替换保存路径为分段式提交接口；移除普通 `applyChanges` 调用。
5) 保持 UI 与动画不变；用返回 `uri` 更新缩略图与跳转。
6) 能力检测与 SaveButton 降级实现（仅当设备不支持）。
7) 全量测试与性能调优，灰度发布。

## 风险与缓解
- 设备不支持分段式：提前检测并自动降级到 SaveButton 快门路径。
- 高分辨率导致内存压力：优先 Canvas 合成，必要时分块或降采样；控制 `ImagePacker` 质量参数。
- 图库提交失败：沙箱兜底与重试队列，避免用户数据丢失。
